## What changed today

**The runtime.** webtweak 1.0 is now a **website you visit** that edits files on your disk through the
browser. Not a local Node server, not `npx`, not a desktop app, no terminal. This reverses the shape the
whole repo is built around: `webtweak.js` is a Node server in its entirety and most of it does not survive.

**Firefox and Safari fidelity.** Supported at **reduced fidelity, never parity**. Not an engineering choice.
Mozilla filed a *harmful* standards position on the File System Access API local-disk pickers and WebKit's is
negative, so silent in-place writes are Chromium-only. Everywhere else a save is a download and the reconcile
loop needs a manual re-open.

## The trap in this map, and it caught this session twice

**Two of today's decisions were reached by AI agents agreeing with each other, and both were wrong in ways
only measurement caught.**

- "A restart rotates the origin, so switching Project is safe" - false. An origin is (scheme, host, port), the
  default port is fixed at 8723, and a restart never evicts a service worker. Recorded on the now-closed
  [#16](https://github.com/stueydubs/webtweak/issues/16). **That flaw is live in shipped 0.8.x today.**
- "Point your download at the project folder" - two agents gave opposite answers, and both were right about a
  narrower case than they claimed. Neither predicted the pre-filled filename in Chrome's save dialog, which is
  the thing that actually decides the outcome. It only appeared when a human sat and clicked.
  ([#23](https://github.com/stueydubs/webtweak/issues/23))

So: **treat any claim on this map that has not been measured as a lead, not a fact.** Where a ticket says
something is established, check whether it was established by reading or by doing.

## State of the frontier

`#19` was the hinge and it has **landed**. The write-up is 890 lines on branch `research/browser-local-files`
at `dadfc13`, unpushed, and the ticket is still open for a human to resolve. Note the ticket carries an
**earlier agent's findings marked unverified** as well - read the second comment, not the first.

The headline: **the architecture works, and it was demonstrated rather than argued.** A service worker read a
real windows-1252 page and its stylesheets from an actual directory handle and the browser rendered it with
`characterSet: windows-1252`, no replacement characters, relative and root-absolute CSS both applying.

Three findings worth knowing before touching #20, #21 or #22:

- Service worker **scope** selects which documents a worker controls, not which URLs it may intercept. Root-absolute
  references are not the obstacle the first pass implied.
- A handle survives reload, tab close and browser restart via IndexedDB, but the **permission** does not survive a
  same-tab navigation, and `requestPermission()` rejects without a gesture. So 1.0 re-authorises every visit unless
  [#25](https://github.com/stueydubs/webtweak/issues/25) says otherwise.
- **`createWritable()` without `keepExistingData` truncates the file to zero bytes on close.** Bail on an error and
  the user's file is gone. Nothing guards this. It sits directly on the save path.

It also **disagreed** with the earlier comment twice, which is the point of having re-run it: `<base href>` does fix
root-absolute references, and a cross-origin handle `postMessage` fires `messageerror` at the receiver rather than
throwing `DataCloneError` at the sender.

## Notes on #15 specifically

The map's differentiator line was corrected earlier today and it bears directly on this ticket: **the
differentiator is never mangling a hand-written file, not the AI.** Pinegrow already runs Claude Code with
file-edit permissions on by default, so "Claude writes the CSS" is not a gap 1.0 closes - it is a gap that is
already closed, by them. What Pinegrow structurally cannot do is leave your file alone.

Also relevant: [#3](https://github.com/stueydubs/webtweak/issues/3) found that Pinegrow and Utopia both inject
an identity attribute and strip it before disk. That is a live option for webtweak now
([#14](https://github.com/stueydubs/webtweak/issues/14), retitled today from "serve time" to "render time"),
and it changes what counts as a conceded gap.
